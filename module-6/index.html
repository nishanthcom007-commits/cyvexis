SECTION 01 // ARCHITECTURE ☁️

The Shared Responsibility Model & Cloud Misconfigurations

The Core Reality: Cloud service providers (AWS, Google Cloud, Microsoft Azure) secure the underlying hardware, hypervisors, and data center facilities ("Security of the Cloud"). However, the customer retains sole responsibility for configuring access control, operating systems, network firewalls, and data assets ("Security in the Cloud").

Critical Misconfigurations:

  • Publicly Accessible Cloud Storage Buckets: Storage containers (AWS S3, Azure Blob, GCS) configured with public read/write ACLs, exposing database dumps, system backups, and sensitive customer PII to automated internet scanners.
  • Permissive IAM Roles: Wildcard permissions (Action: "*", Resource: "*"), excessive administrative policies assigned to temporary worker roles, and forgotten long-lived root credentials.
🛡️ Key Defense Protocol

Enforce Least Privilege & CSPM: Strictly enforce Least Privilege RBAC policies. Enable global Block Public Access (BPA) on all cloud storage buckets, and run continuous Cloud Security Posture Management (CSPM) audits to detect drifting configurations.

SECTION 02 // SECRETS HYGIENE 🔑

API Keys, Secrets Management & Code Leaks

The Attack Vector: Developers frequently hardcode API keys, JWT signing tokens, database connection strings, and private SSH certificates directly into source code files, configuration manifests, or uncommitted .env templates.

Git Scraping Bots: Threat actors continuously monitor the public GitHub and GitLab event feeds using high-speed automated scrapers. When a commit containing credentials is push-published, automated adversary bots harvest and exploit the keys within under 60 seconds to launch cryptomining clusters or exfiltrate production databases.

  • Automated Secrets Scanning: Integrate pre-commit hooks and CI/CD secret scanning engines (e.g., TruffleHog, GitGuardian, GitHub Secret Scanning) to halt git pushes containing credential entropy.
  • Dedicated Secret Stores: Never store static plaintext keys in code or deployment repos. Dynamically retrieve secrets at runtime from centralized vaults (HashiCorp Vault, AWS Secrets Manager, Doppler, GCP Secret Manager).
  • Short-Lived Ephemeral Tokens: Implement auto-rotating, short-lived IAM session credentials instead of permanent root-level API tokens.
🛡️ Key Defense Protocol

Zero Secrets in Git: Enforce strict pre-commit verification hooks. If a credential is ever accidentally committed, treat it as immediately compromised—revoke and rotate the key instantly rather than attempting to delete the commit.

SECTION 03 // DATA COMPLIANCE 📜

Data Classification & Privacy Regulations (GDPR & DPDP)

Enterprise Data Tiers: Organizations must categorize all digital assets into rigorous tiers to determine applicable security controls:

  • Public Tier: Marketing copy, press releases, publicly available documentation. Requires basic integrity verification.
  • Internal Tier: Non-sensitive team memos, architectural roadmaps, and internal handbook guides. Restrict to active employees.
  • Confidential / Restricted: Proprietary source code, financial ledgers, algorithmic trade secrets, and core network topology diagrams.
  • Regulated PII (Personally Identifiable Information): Government IDs (Aadhaar, SSN), biometric identifiers, payment card data (PCI-DSS), and medical health records.

Privacy Compliance Essentials: Regulations like the European Union's GDPR and India's Digital Personal Data Protection (DPDP) Act mandate strict data minimization (collecting only what is strictly necessary), storage limitation (purging records when business purpose concludes), and explicit affirmative consent.

🛡️ Key Defense Protocol

Cryptographic Hygiene: Enforce AES-256 encryption for all data at rest across object storage and relational databases, and mandate TLS 1.3 for all data in transit across internal and external APIs.

SECTION 04 // GOVERNANCE 👁️

Shadow IT & Third-Party SaaS Governance

The Threat of Shadow SaaS: Employees often register for unvetted third-party productivity tools, document converters, and public generative AI engines using corporate credentials, pasting proprietary IP, client source code, and unredacted databases into external cloud infrastructure without SecOps approval.

Token & OAuth Scope Hijacking: Rogue browser extensions and malicious third-party SaaS apps request over-privileged OAuth scopes (such as https://mail.google.com/: "Read, compose, send, and permanently delete all your emails"). Users grant permission with a single click, granting adversaries persistent API-level access to corporate inboxes without triggering credential alerts.

  • Cloud Access Security Brokers (CASB): Monitor and block unauthorized data uploads to unsanctioned cloud platforms.
  • Sanctioned SaaS Catalogs: Require enterprise authentication through company-approved Single Sign-On (SSO) portals with pre-vetted data privacy agreements.
  • Continuous OAuth Auditing: Periodically review and revoke third-party application permissions and browser extension policies across the enterprise.
🛡️ Key Defense Protocol

Centralized OAuth Authorization: Prohibit employees from self-authorizing third-party cloud apps. Enforce administrative approval for all OAuth grants that request read or write permissions to enterprise mail, files, or identity directory resources.
